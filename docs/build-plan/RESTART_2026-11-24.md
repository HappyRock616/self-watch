# Restart build plan (2026-11-24)

HappyRock restarted Self Watch: build the pages and changes agreed in
[CARDS_PLAN.md](../CARDS_PLAN.md), [FOOD_UI_PLAN.md](../FOOD_UI_PLAN.md) and `tools/fooddb/V2_PLAN.md` (private),
plus the Devices page for several devices. Branch `dev`. Nothing is pushed or released without HappyRock's OK.
No device test or install until HappyRock approves it (README §2a test gate); take the device lock first.

## Rules for every workstream

- Cards and screens use the theme's color tokens only (Dark / Light / System, and every accent color theme);
  no hard-coded colors. Check each new card in all themes and at 1.0×, 1.5× and 2.0× font size (component gallery).
- Intuitive first: one main number per small card, plain labels, tap for detail, strong status colors
  (on track / close / off) that come from the theme.
- Watch battery is critical. Sampling and sync choices are checked against Gadgetbridge and Garmin's documented
  defaults; never poll the watch, never raise a rate without a reason written down.
- Tests: unit tests for math and loaders; Robolectric for screens; the full suite passes before each commit.
- Commits without Co-Authored-By lines (repo rule); no personal names.

## Workstream A: cards and the Body / Activity / Food pages (this session)

1. Card framework: every card in two sizes (small = half width, one number; large = full width), size chosen
   in Edit cards; any card on any tab (Body, Activity, Food); a 2-column grid that packs small cards in pairs.
2. Defaults: one layout per tab (no main-goal presets), shown only when the user's devices record the data,
   with the backup list from CARDS_PLAN.md. Existing users keep their layout.
3. New cards: Body today, Activity goals, Recent activities (tall list), Daily balance (replaces the fixed
   calories-left header), Weight goal (calorie recommendation over time, BMI), Sport progress, Food groups.
4. The optional catalog from CARDS_PLAN.md (Gadgetbridge and Garmin Connect cards), each showing
   "Your devices don't record this" when there's no data source.
5. Onboarding goal step copy; goals screen covers every goal the goal cards show.

## Workstream B: food database v2 in the app, search, food screens (own session)

FOOD_UI_PLAN.md phases 1–3 and V2_PLAN.md "App work": schema 2 reader (extra nutrients, category, diet flags,
allergens), the new search (port of `tools/fooddb/search_test.py`), food detail sheet redesign, Day nutrition
screen, diet and allergen setting with targets, custom food v2 fields. Exposes the v2 nutrient fields in the
model so Workstream A's Daily balance can show fat types after both land. Does not touch card files.

## Workstream C: Devices page and sampling rates (own session)

- Devices page: one card per device (watch, strap, scale, other), connect / disconnect per device, several
  connected at once, trash to remove a device (keeps its data unless chosen), 3-second hold to reset that
  device's data (keeps workouts), exclusive-watch switch per device (off by default), status and last sync.
- Sensor priority: a connected heart-rate strap or sensor always wins over the watch's heart rate.
- Sampling and sync audit: watch logging settings (heart rate, stress, SpO2 sleep-only vs all day, respiration,
  HRV), sync triggers and BLE connection parameters, checked against Gadgetbridge and Garmin defaults; a written
  table of every rate with the reason, and changes only where a rate is wasteful or too coarse.

## Order and merge

A, B and C run in parallel on their own branches (B and C in worktrees). HappyRock decides when to merge them
into `dev`. Then: full test suite, component gallery screenshots in all themes, food database v2 publish
(`foods-manifest-v2.json`), and a device test only after HappyRock approves.
